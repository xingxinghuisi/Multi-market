# v0.20 – MIRAO 推送订阅与行情稳定性

This release integrates hourly long/short reports and large-trade alerts into personal PWA subscriptions, improves hourly delivery recovery, and prevents an unavailable stock gateway from blocking crypto quotes.
本版本将小时多空播报和大额成交提醒整合为个人 PWA 订阅，完善小时播报失败重试，并修复股票网关不可用时阻塞加密行情的问题。

## Push Subscriptions / 推送订阅

- Added account-owned subscriptions under Alerts → Push Subscriptions, with symbol selection and independent hourly long/short and large-trade switches. Price-step alerts retain their existing rules.
  在「提醒 → 推送订阅」新增个人订阅管理，支持选择币种、独立开启小时多空播报和大额成交提醒；价格步进提醒继续使用现有规则。
- Large-trade alerts support per-symbol USDT notional thresholds and per-account cooldowns. Subscription switches are independent of market-data collection and watchlist membership.
  大额成交提醒支持每个币种的 USDT 名义金额阈值和个人提醒间隔；订阅开关与行情采集、是否加入关注列表相互独立。
- Futures details now expose completed-hour global account, top-trader account, top-trader position and taker buy/sell ratios, including prior-period comparisons. Unavailable data is explicitly reported.
  合约详情展示完整小时的全体账户、大户账户、大户持仓和主动买卖比，并提供上期对比；数据不可用时明确提示。

## Large-Trade Data / 大额成交数据

- Uses Binance USD-M public `aggTrade` WebSocket streams. Each aggregate is checked against the user's threshold using price × quantity; the buyer-maker flag determines the aggressor direction.
  使用 Binance USD-M 公开 `aggTrade` WebSocket 数据，按每笔聚合成交的价格 × 数量与用户阈值比较，并根据买方是否为挂单方判断主动买卖方向。
- Messages include price, original quantity, notional amount, direction, event time and the observed buy/sell notional difference over a window of up to five minutes. Observation totals reset after disconnection.
  消息包含成交价、原始数量、名义金额、方向、成交时间，以及最多五分钟观测窗口内的主动买卖金额差额；连接中断后重新统计观测窗口。
- These alerts identify large aggregated trades, not individual wallets or confirmed whale identities. The observed buy/sell difference is not actual capital inflow or outflow. This release covers supported USDT contracts, not Spot or on-chain transfers.
  此功能识别大额聚合成交，不能识别具体钱包或确认巨鲸身份；主动买卖差额不等于真实资金流入或流出。本轮覆盖支持的 USDT 合约，不包含现货或链上转账。

## Delivery and Recovery / 投递与恢复

- The API resolves each account's Telegram recipient and records notification history. Unbound users receive in-app records; only the legacy default account retains the deployment-level recipient fallback.
  API 按账户解析 Telegram 接收目标并保存通知历史；未绑定用户保留站内通知，只有旧 default 账户保留服务器默认接收目标兼容。
- Added persistent subscription/event keys to suppress repeated submissions. Failed deliveries can retry the same event without duplicating notification history; uncertain pending deliveries are not blindly resent.
  新增持久化订阅／事件键，抑制重复提交；失败事件可沿用同一事件键重试，不重复创建通知历史；结果不明的 pending 投递不会盲目重发。
- Hourly reports retry missing data, request failures and failed deliveries every 60 seconds, up to 11 attempts, while keeping the original completed hour. Successful recipients are skipped during retries, and retries stop before the next hour's task is due.
  小时播报遇到数据缺失、请求失败或投递失败时，每 60 秒重试，最多尝试 11 次，始终保留原完整小时；重试跳过已成功接收者，并在下一小时任务到期前停止。
- Worker restarts check the latest due hour and use the same durable event key. Diagnostics now report missing data fields or HTTP status codes without logging credentials. Older hours are not automatically backfilled.
  Worker 重启时补查最近已到播报时间的小时，继续使用相同的持久化事件键；日志显示缺失的数据项或 HTTP 状态码，不输出凭据；不会自动补发更早的小时。

## Market Reliability / 行情稳定性

- Moomoo streaming now uses the SDK's asynchronous connection mode and bounded connection waits. Binance Spot/Futures continue processing when OpenD is stopped or unavailable.
  Moomoo 行情采用 SDK 异步连接并限制连接等待；OpenD 停止或不可用时，Binance 现货／合约继续处理行情。
- Market sources retry independently, including sources with no enabled assets at startup.
  各行情源独立重试，启动时暂时没有启用资产的行情源也会继续检查新增资产。
- Production recovery verified remembered-account OpenD login, all eight configured stock subscriptions and received stock quotes after restarting the market worker. This operational recovery does not change account credentials or grant market permissions.
  生产环境已验证 OpenD 记住密码登录恢复，并在重启行情 Worker 后确认现有 8 个股票标的订阅成功、收到股票行情；此次运维恢复不修改账户凭据，也不新增行情权限。

## Deployment and Verification / 部署与验证

- API startup adds subscription and delivery tables without replacing existing databases. Existing subscription choices remain intact; the legacy owner's hourly selections migrate only on the first subscription-table upgrade. Large-trade alerts require an explicit subscription.
  API 启动时增量创建订阅和投递表，不替换现有数据库；保留已有订阅选择，仅在首次创建订阅表时迁移旧账户小时播报选择；大额成交提醒需主动订阅开启。
- Deploy the API, hourly worker and large-trade worker together when upgrading from v0.19. The hourly retry fix alone requires only an app image rebuild and recreation of `crypto_metrics_worker`.
  从 v0.19 升级时，应一起更新 API、小时播报 Worker 和大额成交 Worker；单独部署小时重试修复时，只需重建应用镜像并更新 `crypto_metrics_worker`。
- Passed 56 Python regression tests and 11 JavaScript tests. Production logs confirmed Binance quote updates, accepted Telegram hourly delivery, and Moomoo stock subscriptions and quotes.
  通过 56 项 Python 回归测试和 11 项 JavaScript 测试；生产日志已确认 Binance 行情更新、Telegram 小时播报投递成功，以及 Moomoo 股票订阅和行情接收。

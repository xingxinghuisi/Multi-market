# v0.21 – MIRAO Whale Positions & PWA Updates
# v0.21 – MIRAO 巨鲸仓位与 PWA 更新优化

This release adds automatic public-wallet discovery for Hyperliquid / trade.xyz perpetuals, verified position changes and unrealized P&L, concise Telegram alerts, and a fix for repeated PWA refreshes.
本版本新增 Hyperliquid / trade.xyz 永续合约公开钱包自动发现、真实仓位变化与未实现盈亏展示，精简 Telegram 推送，并修复 PWA 反复刷新的问题。

## Automatic Whale Discovery / 自动发现巨鲸

- Added Alerts → On-chain Whale Positions. Users choose a market, minimum USD position value and wallet/market notification interval without entering wallet addresses. Subscriptions can be paused or deleted independently of Binance alerts and quote collection.
  新增「提醒 → 链上巨鲸仓位」。无需填写钱包地址，可选择市场、最低美元仓位价值和同地址同市场提醒间隔，支持暂停与删除；与 Binance 提醒和行情采集相互独立。
- Discovers both public counterparties from observed trades, keeps a persistent candidate pool, and verifies holdings through official `clearinghouseState` snapshots. No wallet private key, trading permission or account API key is required.
  从观测成交的买卖双方发现公开地址，持久保存候选池，并通过官方 `clearinghouseState` 快照核验持仓；不需要钱包私钥、交易权限或账户 API Key。
- Replaced the initial four-market allowlist with the full currently listed, non-delisted official `xyz` catalog. Added market search, hourly catalog refresh and validation before creating subscriptions. Only explicitly enabled markets are monitored.
  将最初四个品种的白名单扩展为官方 `xyz` 目录中全部当前可用、未退市的合约，新增搜索、每小时目录刷新和订阅前核验；只监控用户明确开启的市场。

## Positions and P&L / 仓位与盈亏

- Added discovery, opening, increase, reduction, closure and reversal events by comparing signed quantities between verified snapshots. Initial holdings are labeled as pre-existing discoveries; price-only changes do not imply trading activity.
  根据两次核验快照的签名数量识别新发现已有仓位、新开仓、加仓、减仓、平仓和反向开仓；首次发现不冒充刚开仓，价格变化本身不算加减仓。
- Position cards and new messages display source-provided entry price, current leverage, notional value and `unrealizedPnl`. Profit, loss and zero are distinguished; missing fields and older snapshots remain unavailable. Closed positions do not fabricate realized profit.
  仓位卡片与新消息展示来源提供的开仓均价、当前杠杆、仓位名义价值和 `unrealizedPnl`，区分浮盈、浮亏与真实零值；缺失字段和旧快照显示“未提供”，平仓不编造已实现收益。
- Added service heartbeat, trade connection state, subscribed markets, verification times, queue depth and error visibility. Stale positions are marked, and malformed or outdated snapshots cannot create false closure events.
  页面展示服务心跳、成交连接、已订阅市场、核验时间、排队数和异常；过期仓位明确标记，缺失或过期快照不会生成虚假平仓。

## Concise Telegram Alerts / 精简 Telegram 提醒

- New messages put the market and action first, followed by position value, entry/leverage, unrealized P&L, a shortened address and Beijing time. Increases and reductions show the net quantity change; their amount is labeled as the remaining position value, not the value of that adjustment.
  新消息首行显示品种与动作，随后显示仓位价值、均价及杠杆、浮动盈亏、短地址和北京时间；加减仓数字表示仓位数量净变化，金额明确为“剩余仓位”，不代表本次调整金额。
- Retained full addresses and snapshot details in stored events and the web view. Existing notifications and Telegram messages are not rewritten or replayed.
  事件数据与网页保留完整地址和快照详情；已有通知和 Telegram 消息不改写、不补发。
- Reuses personal Telegram bindings, account notification history, durable event deduplication and bounded explicit-failure retries. Wallet/market cooldowns still apply, so a recorded web event may not generate a Telegram alert; cooldown-suppressed events are not queued for later delivery.
  复用个人 Telegram 绑定与账户通知历史，并提供持久事件去重和有限失败重试；仍遵守同地址同市场冷却间隔，因此网页记录的事件不一定推送，冷却期间被抑制的事件不会排队补发。

## PWA Reliability / PWA 稳定性

- Fixed reload loops caused by stale cached scripts and newer server versions. Update attempts are bounded across navigation, including environments where session storage is blocked, and pending writes or active forms defer automatic updates.
  修复缓存旧脚本与服务器新版本不一致造成的无限刷新；限制跨页面刷新次数，兼容会话存储被禁用的环境，存在待完成写入或正在填写的表单时延后更新。
- Versioned the public shell, module imports and service worker consistently, and improved cache revalidation. Private APIs and market data remain excluded from the offline cache.
  统一公开页面、模块引用和 Service Worker 的版本，改善缓存重新验证；私人接口和行情数据继续排除在离线缓存之外。
- Added the installed frontend build version to About MIRAO. This identifies the code currently loaded by the device.
  在「关于 MIRAO」增加当前前端构建版本，显示设备实际加载的版本。

## Deployment and Verification / 部署与验证

- Added `whale_position_worker` to Docker Compose and additive whale tables using the existing shared database volume. Back up production data before upgrading from v0.20, rebuild the application image, and recreate the API and whale position worker. Run one whale position worker replica.
  Docker Compose 新增 `whale_position_worker`，巨鲸数据表以增量方式加入现有共享数据库。从 v0.20 升级前先备份生产数据，重建应用镜像并更新 API 与巨鲸仓位 Worker；巨鲸仓位 Worker 只运行一个实例。
- `git pull` downloads source only; it does not update running containers. Existing market, news, Binance large-trade and OpenD services do not need recreation for these changes. A message-copy-only upgrade from the preceding whale build needs only a rebuilt image and recreation of `whale_position_worker`.
  `git pull` 仅下载源码，不更新正在运行的容器；本次不需要重建现有行情、新闻、Binance 大额成交或 OpenD 服务。已部署上一版巨鲸功能、仅更新消息文案时，重建镜像并更新 `whale_position_worker` 即可。
- Passed 95 Python regression tests and 22 JavaScript tests, JavaScript syntax checks and Git whitespace checks. Earlier browser checks covered subscription management, version display, P&L rendering, responsive themes and bounded PWA updates. Release publication does not itself deploy the VPS.
  通过 95 项 Python 回归测试、22 项 JavaScript 测试、JavaScript 语法检查和 Git 空白检查；此前浏览器检查覆盖订阅管理、版本显示、盈亏展示、响应式主题与 PWA 有限自动更新。发布 Release 本身不会部署 VPS。

Coverage is limited to observed Hyperliquid / trade.xyz markets and discovered candidates. This is not a complete historical or cross-exchange whale index, and it cannot expose Binance customers' private positions. Quiet wallets, short-lived positions, connection gaps, pool capacity and upstream limits can cause omissions. Same-named Binance and trade.xyz instruments are separate markets. Position events describe net changes between snapshots, not individual fills or exact opening times.
当前覆盖限于观测到的 Hyperliquid / trade.xyz 市场与已发现候选，并非全网或全历史巨鲸索引，也无法获取 Binance 用户的私人仓位。静默钱包、短暂持仓、连接中断、候选池容量和上游限流可能造成遗漏；Binance 与 trade.xyz 同名品种属于不同市场。仓位事件表示快照之间的净变化，不代表逐笔成交或精确开仓时间。
